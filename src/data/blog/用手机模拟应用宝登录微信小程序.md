> 仅用于个人账号与学习研究。原理是把自己在应用宝渠道抓到的登录凭证注入到游戏登录流程，**账号互踢、凭证过期、封号风险都需要自行承担**。抓包文件里含手机号等实名信息，不要外传。

## 一、原理：登录凭据从哪来

墨迹大侠（行侠仗义五千年）的登录会请求应用宝渠道的鉴权接口：

```text
https://web-a5h5.hanyinkj.cn/auth/auth_sdk/auth.php?device_id=<设备IDFA>
```

响应 JSON 里返回三个关键字段，它们就是这一次登录的"临时身份证"：

| 字段 | 含义 | 说明 |
| :--- | :--- | :--- |
| `uin` | 账号 ID | 整数 |
| `authtime` | 鉴权时间戳 | 整数，会过期 |
| `loginkey` | 登录密钥 | 32 位十六进制字符串，会过期 |

拿到自己大号的这三个值后，把它塞进游戏的登录流程即可。两个平台的差别只在于"塞"的位置：

| | 安卓 | iOS |
| :--- | :--- | :--- |
| 改包位置 | 游戏进程内存（Frida） | Mac 上的 mitmproxy，经 WireGuard 隧道接管鉴权流量 |
| 技术要求 | 需 root 或修改版 APK | 不越狱，装 AmneziaWG 客户端 |
| 优点 | 一次注入，全程生效 | 不依赖越狱，凭证按设备自动匹配，日常零操作 |

为什么 iOS 上只改鉴权响应就够用：游戏的**数据连接**（WebSocket / 原始 TCP）和微信自己的流量都不需要经手，我们让手机的 `AllowedIPs` 只包含"DNS + 鉴权服务器"这几个 IP，把这些流量收进 WireGuard 隧道交给 Mac 上的 mitmproxy；游戏数据依然直连。这样改包只发生在登录那一瞬，游戏的延迟和稳定性不受影响。

## 二、第一步：抓取自己的凭证（Windows + Fiddler，两端通用）

1. Windows 上安装 Fiddler，手机连接 Fiddler 代理（或直接在 Windows 上打开应用宝，登录你的大号）。
2. 登录一次应用宝渠道的墨迹大侠，让 Fiddler 抓到 `auth.php` 的响应。
3. 从响应 JSON 里取 `uin`、`authtime`、`loginkey` 三个值。

手工找太麻烦，可以用 FiddlerScript 自动提取并生成文件。依次打开菜单 **Rules → Customize Rules**，在 `OnBeforeResponse` 里加入：

```javascript
static function OnBeforeResponse(oSession: Session) {
    var targetUrl = "/auth/auth_sdk/auth.php";
    if (!oSession.uriContains(targetUrl)) return;

    var resBody = "";
    try {
        resBody = oSession.GetResponseBodyAsString();
    } catch (e) {
        // gzip 解压失败时退化为读取原始字节
        resBody = System.Text.Encoding.UTF8.GetString(oSession.responseBodyBytes);
    }

    var uin = (new System.Text.RegularExpressions.Regex("\"uin\":(\\d+)")).Match(resBody);
    var authtime = (new System.Text.RegularExpressions.Regex("\"authtime\":(\\d+)")).Match(resBody);
    var loginkey = (new System.Text.RegularExpressions.Regex("\"loginkey\":\"([^\"]+)\"")).Match(resBody);

    if (!uin.Success || !authtime.Success || !loginkey.Success) return;

    FiddlerObject.log("uin = " + uin.Groups[1].Value);
    FiddlerObject.log("authtime = " + authtime.Groups[1].Value);
    FiddlerObject.log("loginkey = " + loginkey.Groups[1].Value);

    // 可选：自动把三个值写进脚本模板，生成可直接使用的文件
    // 【按自己电脑的实际路径修改】
    var templatePath = "C:\\Users\\xxx\\Desktop\\login.js.base";
    var outPath = "C:\\Users\\xxx\\Desktop\\login.js";
    try {
        var content = System.IO.File.ReadAllText(templatePath)
            .Replace("{{UIN}}", uin.Groups[1].Value)
            .Replace("{{AUTHTIME}}", authtime.Groups[1].Value)
            .Replace("{{LOGINKEY}}", loginkey.Groups[1].Value);
        System.IO.File.WriteAllText(outPath, content);
        FiddlerObject.log("已生成：" + outPath);
    } catch (ex) {
        FiddlerObject.log("写文件失败：" + ex.Message);
    }
}
```

> 安卓教程里 `login.js.base` 就是这个模板文件，把三个变量换成占位符即可。iOS 方案不需要 `login.js`，直接把三个值填进下面的 mitmproxy 脚本。

## 三、第二步 A：安卓端用 Frida 注入

1. 手机准备好 Frida 环境：已 root 的设备直接跑 `frida-server`；没有 root 的用 MT 管理器把 Frida Gadget 注入到游戏 APK。
2. 在 `/sdcard/` 下新建 `frida` 目录，把生成好的 `login.js` 放进去。
3. 启动游戏并注入脚本（包名替换成实际包名）：

```bash
adb shell "su -c '/data/local/tmp/frida-server &'"
frida -U -f com.xxx.game -l /sdcard/frida/login.js
```

`login.js` 的核心逻辑是 hook `libil2cpp.so` 的发送函数，在编号 `7009` 的登录包发出前，把包里的 `uin`、`authtime`、`loginkey` 替换掉：

```javascript
var g_uin = {{UIN}}
var g_authtime = {{AUTHTIME}}
var g_loginkey = "{{LOGINKEY}}"

// hook 发送函数后，在登录包里写入上面三个值
ptrvar.add(0x10).writeInt(g_uin);
ptrvar.add(0x18).writeInt(g_authtime);
write_string(loginkey_ptr, g_loginkey);
```

几个容易踩的点：

- 小程序版和 App 版的 `libil2cpp.so` 偏移不同，教程里的脚本是用特征码扫描定位函数的，如果扫不到地址，需要按当前版本重新找偏移。
- 脚本里 `cmd == 7009` 会被置 0、心跳包直接跳过，属于正常的"只劫持登录"处理，不要删。
- 游戏更新后偏移和特征码可能变化，需要重新适配。

## 四、第二步 B：iOS 端用 WireGuard + mitmproxy（推荐）

iOS 不越狱改不了进程内存，所以换到网络层：让 iPhone 的鉴权流量经 WireGuard 隧道送到 Mac，由 mitmproxy 把 `auth.php` 响应里的三个字段替换成你的大号凭证。

日常使用体验：**VPN 一直开着就行**，打开游戏自动就是大号，不用改代理、不用每次操作。

### 1. 安装 mitmproxy

```bash
brew install mitmproxy
```

### 2. 保存 addon 脚本

新建 `mjdx_rewrite.py`，它做两件事：按 `device_id` 改写鉴权响应，以及把鉴权域名固定解析到隧道里的 IP（防止域名换 IP 后绕过隧道）：

```python
"""mitmproxy addon：改写 auth.php 响应 + 钉住鉴权域名解析"""
import json
from mitmproxy import ctx, dns, http
from mitmproxy.net.dns import classes, types

TARGET = "/auth/auth_sdk/auth.php"

# 设备 IDFA -> (uin, authtime, loginkey)
# IDFA 从 mitmweb 日志里看，见"多设备"一节
CREDENTIALS = {
    "XXXXXXXX-XXXX-XXXX-XXXX-XXXXXXXXXXXX": (
        12345678, 1793974417, "0123456789abcdef0123456789abcdef"
    ),
}

# 鉴权域名固定解析到这些 IP，必须和手机配置里的 AllowedIPs 一致
PINNED_IPS = {
    "h5api.hanyinkj.cn": ["212.129.231.170"],
    "web-a5h5.hanyinkj.cn": ["150.158.220.72"],
}


class DnsPin:
    def dns_request(self, flow: dns.DNSFlow):
        if not flow.request.questions:
            return
        q = flow.request.questions[0]
        ips = PINNED_IPS.get(q.name.rstrip("."))
        if not ips or q.type != types.A:
            return
        flow.response = flow.request.succeed(
            [
                dns.ResourceRecord(
                    name=q.name,
                    type=types.A,
                    class_=classes.IN,
                    ttl=300,
                    data=bytes(int(p) for p in ip.split(".")),
                )
                for ip in ips
            ]
        )
        ctx.log.warn(f"[mjdx] DNS pinned {q.name} -> {ips}")


class RewriteAuth:
    def response(self, flow: http.HTTPFlow):
        if TARGET not in flow.request.pretty_url:
            return
        if not flow.response or flow.response.status_code != 200:
            return

        device_id = flow.request.query.get("device_id", "")
        creds = CREDENTIALS.get(device_id)
        if creds is None:
            ctx.log.warn(f"[mjdx] 未匹配设备 device_id={device_id}，原样放行")
            return

        try:
            data = json.loads(flow.response.get_content())
        except Exception:
            return
        if not isinstance(data, dict) or data.get("ret") != 0:
            return

        old_uin = data.get("uin")
        uin, authtime, loginkey = creds
        data.update(uin=uin, authtime=authtime, loginkey=loginkey)
        flow.response.set_content(json.dumps(data, separators=(",", ":")).encode())
        ctx.log.warn(f"[mjdx] {device_id}: uin {old_uin} -> {uin}")


addons = [DnsPin(), RewriteAuth()]
```

### 3. 在 Mac 上启动

```bash
mitmweb --mode wireguard --set rawtcp=true \
  --set ignore_hosts="weixin\.qq\.com|servicewechat\.com|qq\.com|qpic\.cn|gtimg\.cn|tencent\.com|wechat\.com" \
  -s mjdx_rewrite.py
```

- WireGuard 服务端监听 `51820/UDP`，浏览器会自动打开 `127.0.0.1:8081` 管理界面。
- `ignore_hosts` 里的微信系域名只放行、不解密，避免微信自己的流量出问题。**不要**把 `hanyinkj.cn` 排除掉，否则就改不了包了。
- Mac 防火墙需要放行 `mitmproxy` 的传入连接（系统设置 → 网络 → 防火墙）。
- Mac 不能睡眠，可以这样启动：`caffeinate -i mitmweb ...`。

### 4. iPhone 安装 WireGuard 客户端

大陆区 App Store 已下架 WireGuard 官方客户端，用 **AmneziaWG**（WireGuard 协议的分支，免费，完全兼容标准配置）：

1. App Store 搜索 `AmneziaWG` 安装。
2. Mac 的 mitmweb 顶部 **Capture** 页面会显示 WireGuard 客户端配置和二维码，手机直接扫码导入；也可以把配置文本存成 `.conf` 文件 AirDrop 过去导入。
3. 导入后检查（或手动改成）以下配置：

```ini
[Interface]
PrivateKey = <自动生成，不要改>
Address = 10.0.0.1/32
DNS = 10.0.0.53

[Peer]
PublicKey = <自动生成，不要改>
AllowedIPs = 10.0.0.53/32, 212.129.231.170/32, 150.158.220.72/32
Endpoint = 192.168.0.103:51820
```

- `Endpoint` 必须是 **Mac 的局域网 IP**（形如 `192.168.x.x:51820`），不是本机回环地址。
- `AllowedIPs` 只放 DNS 和鉴权 IP，游戏数据和微信都直连；如果全部写成 `0.0.0.0/0`，手机全部流量都会绕 Mac，速度和耗电都会变差。
- `AllowedIPs` 里的 IP 必须和脚本里的 `PINNED_IPS` 一致。鉴权域名换 IP 时用 `dig +short h5api.hanyinkj.cn`、`dig +short web-a5h5.hanyinkj.cn` 查最新的，两处一起更新。

### 5. 安装并信任证书

**这步不做会登录失败**：mitmproxy 要解密 `hanyinkj.cn` 的 HTTPS，App 校验不过就拒绝登录。

1. 保持 VPN 开启，Safari 访问 `mitm.it`，下载 Apple 版描述文件。
2. 设置 → 通用 → VPN与设备管理 → 安装该描述文件。
3. 设置 → 通用 → 关于本机 → **证书信任设置** → 打开 mitmproxy 的完全信任开关。

### 6. 登录并验证

1. 把墨迹大侠 App 从后台彻底划掉，冷启动。
2. 正常走微信登录，进入游戏。
3. 看昵称、等级、进度——已经是应用宝那边的大号就成功了，同时 mitmweb 日志里会出现：

```text
[mjdx] 2250A3B3-...: uin 12345678 -> 21356458
```

登录成功后可以直接把 VPN 关掉，实测进游戏后断线重连仍然是同一个账号；下次冷启动登录前再打开即可。如果希望全程无感，就一直开着 VPN。

**Mac 关机或不在线时**：VPN 开着会导致 DNS 不通、手机整体没网。此时把 VPN 关掉即可，登录会回到设备自己的小号。

### 7. 多设备、多账号

`auth.php` 请求里带的是**设备的** IDFA，不是账号的，所以同一台手机不管登哪个号 IDFA 都不变。给每台设备配一个账号即可：

1. 新设备先导入配置、开 VPN 登录一次（此时表里没有它，登的是自己的小号）。
2. 看 mitmweb 事件日志里打印的 `未匹配设备 device_id=XXXX`。
3. 把 `IDFA → (uin, authtime, loginkey)` 加进脚本的 `CREDENTIALS`，重启 mitmweb。
4. 该设备以后每次登录都会自动注入它自己的凭证。

注意：

- 同一台设备只能对应一个账号，想换号就改表里那一行。
- **同一份 WireGuard 配置不要在两台设备同时开**（同密钥会互踢）。只是登录的话，轮流开 VPN 登录、各自关掉即可。
- 需要**多台设备同时在线**时，让 mitmproxy 同时开多个 WireGuard 服务端，每台设备一份独立密钥和端口（同一个进程、同一个脚本、同一个证书）：

```bash
mitmweb \
  --mode wireguard:$HOME/.mitmproxy/phone-a.conf@51820 \
  --mode wireguard:$HOME/.mitmproxy/phone-b.conf@51821 \
  --set rawtcp=true \
  --set ignore_hosts="weixin\.qq\.com|servicewechat\.com|qq\.com|qpic\.cn|gtimg\.cn|tencent\.com|wechat\.com" \
  -s mjdx_rewrite.py
```

首次启动会自动生成密钥文件，启动日志里会分别打印每个端口的完整客户端配置；手机 A 导入 `Endpoint=MacIP:51820` 的那份，手机 B 导入 `51821` 的那份，各自按需收窄 `AllowedIPs`。凭证仍然按 IDFA 自动匹配，无需额外配置。

- 如果 iPhone 关闭了"允许跟踪"，IDFA 可能是全零，多台设备就无法区分了，需要在 设置 → 隐私与安全性 → 跟踪 里给游戏授权。

### 8. 备选：Wi-Fi HTTP 代理（更轻量）

不想装 VPN 的，可以用系统自带的 Wi-Fi 代理，代价是只在家里这个 Wi-Fi 下生效：

```bash
mitmweb --set ignore_hosts="weixin\.qq\.com|servicewechat\.com|qq\.com|qpic\.cn|gtimg\.cn|tencent\.com|wechat\.com" -s mjdx_rewrite.py
```

iPhone：设置 → 无线局域网 → 当前 Wi-Fi 的 ⓘ → 配置代理 → 手动 → 服务器填 Mac 局域网 IP、端口 `8080`。证书步骤同上。DNS 固定那部分用不上（按域名代理不受换 IP 影响），其余原理和注意点都一致。

## 五、常见问题

**登录失败、卡在加载页**
多半是证书没信任。mitmproxy 接管了 `hanyinkj.cn` 的 HTTPS，App 校验不过就拒绝登录。按第 5 步把 mitmproxy 证书完全信任。

**开着 VPN 手机整体没网**
说明 Mac 上的 mitmweb 没在跑、Mac 睡眠了，或者防火墙拦了 `51820/UDP`。先确认 Mac 在线，再检查防火墙；实在不行先关 VPN。

**登录后还是小号**
1. 日志里没有 `[mjdx]` 行 → 请求没命中 `auth.php`，检查域名和路径；
2. 日志里是"未匹配设备" → 把这次的 `device_id` 加进 `CREDENTIALS`；
3. 日志里有改写但游戏还是小号 → 鉴权域名换 IP 了，更新 `PINNED_IPS` 和手机 `AllowedIPs`；
4. 以上都正常但仍是小号 → `uin`/`authtime`/`loginkey` 过期了，回 Windows 重新抓一次。

**凭证多久过期**
以实测为准，表现为"登录后变小号"。过期就重新抓 `auth.php`，只更新表里对应那一行，不用改代码。

**会不会被顶号**
同一个账号在 Windows 应用宝和手机上同时在线会互踢。验证时先把 Windows 端退出。

**出门能不能用**
隧道 Endpoint 是家里 Mac 的内网 IP，蜂窝或外网连不上，所以出门登录不了大号。想在任意网络下用，需要把 Mac 的 `51820/UDP` 映射到公网（frp 等），或者直接把 mitmproxy 部署到有公网 IP 的 VPS 上。

## 六、进阶：把服务挪到公网

如果希望 Mac 不在身边也能登录，可以把整套服务迁到有公网 IP 的 VPS（Oracle Cloud 免费层、轻量云服务器都可以）：

1. 在 VPS 上安装 mitmproxy，拷贝 `mjdx_rewrite.py`。
2. 用同样的命令启动 WireGuard 模式，放行 `51820/UDP`。
3. 手机配置里的 `Endpoint` 改成 `VPS 公网IP:51820`，其余不变。
4. **不要把 mitmweb 的 `8081` 管理界面暴露到公网**；WireGuard 本身有密钥认证，暴露 `51820/UDP` 是安全的。

VPS 的延迟通常只比家宽多十几毫秒，对放置类玩法基本无感，而且不再需要 Mac 常开。
